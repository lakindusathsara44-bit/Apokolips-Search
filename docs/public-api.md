# Apokolips Search Public API v1

The public API exposes search over Apokolips' own first-party SQLite FTS5 index. It does not proxy Google, Bing, or another search provider. A page appears in results only after Apokolips Spider has crawled and indexed it.

## Base URL

For local development:

    http://127.0.0.1:8000

For a future hosted service, use the HTTPS origin configured for the deployment. Do not send API keys over plain HTTP on a public network.

## Authentication

Every public search request requires an API key in the `X-API-Key` header:

    X-API-Key: aps_live_your_key

API keys are generated by an administrator. The database stores only a SHA-256 hash of each high-entropy key. The complete key is returned once at creation time and cannot be retrieved later. If it is lost, create a replacement and revoke the old key.

### Enable public mode

Configure these environment variables before starting the API:

- `APOKOLIPS_PUBLIC_MODE=true` — enables the public deployment security boundary.
- `APOKOLIPS_ADMIN_TOKEN` — a randomly generated secret of at least 32 characters. Keep it private; it controls key management and crawler administration.
- `APOKOLIPS_CORS_ORIGINS` — optional comma-separated exact browser origins, for example `https://apokolips.xyz,https://www.apokolips.xyz`. Wildcard origins are ignored.
- `APOKOLIPS_DB_PATH` — optional path to the persistent SQLite database.
 
PowerShell example (generate a fresh administrator token locally):

    $env:APOKOLIPS_PUBLIC_MODE = "true"
    $env:APOKOLIPS_ADMIN_TOKEN = python -c "import secrets; print(secrets.token_urlsafe(48))"
    $env:APOKOLIPS_CORS_ORIGINS = "https://apokolips.xyz,https://www.apokolips.xyz"
    uvicorn app.main:app --host 127.0.0.1 --port 8000

The command above is suitable for local testing behind a local reverse proxy. A public host must terminate HTTPS and provide secure secret management. Public mode refuses to start if the administrator token is missing or shorter than 32 characters.

In public mode:
- The legacy unauthenticated `/search` route is disabled; use `/api/v1/search`.
- Crawl submission, job inspection/cancellation, crawl history, and operational statistics require the administrator bearer token.
- API-key administration always requires the administrator bearer token.
- The public search endpoint is the only endpoint intended for third-party developer keys.

## Create an API key (administrator)

Send the administrator token as a bearer token. The request can be made in Swagger UI at `/docs` or with curl:

    curl -X POST http://127.0.0.1:8000/admin/api-keys ^
      -H "Authorization: Bearer YOUR_ADMIN_TOKEN" ^
      -H "Content-Type: application/json" ^
      -d "{\"name\":\"My application\",\"requests_per_minute\":60}"

Example request:

    {
      "name": "My application",
      "requests_per_minute": 60
    }

The response includes the full `api_key` exactly once. Store it in your server-side secret manager or environment variables. Never commit it to Git, publish it in frontend JavaScript, or share it in a public repository.

### Manage keys

- `POST /admin/api-keys` — create a key (name and quota).
- `GET /admin/api-keys` — list key metadata; secret values are never returned.
- `DELETE /admin/api-keys/{key_id}` — revoke an active key immediately.

All three require `Authorization: Bearer YOUR_ADMIN_TOKEN`.

## Search

    curl --get http://127.0.0.1:8000/api/v1/search ^
      -H "X-API-Key: aps_live_your_key" ^
      --data-urlencode "q=Apokolips search" ^
      --data-urlencode "page=1" ^
      --data-urlencode "page_size=10"

### Query parameters

| Parameter | Default | Limits | Description |
|---|---:|---:|---|
| `q` | required | 1–200 characters; at most 12 searchable words | Plain-text search query |
| `page` | 1 | 1–10,000 | Result page |
| `page_size` | 10 | 1–20 | Results per page |

All query words use AND matching. Results are ranked with weighted BM25 (title, description, headings, and body). Empty or unsupported queries return HTTP 422.

## Rate limits

Each API key has its own fixed UTC-minute request window. New keys default to 60 requests per minute; an administrator can assign 1–600 requests per minute. The quota is applied atomically in SQLite, including when requests arrive concurrently.

Responses include:
- `X-RateLimit-Limit` — the key's requests-per-minute quota.
- `X-RateLimit-Remaining` — remaining requests in the current minute.
- `X-RateLimit-Reset` — seconds until the quota window resets.
- `Retry-After` — included on HTTP 429 responses.

HTTP 429 means the current key quota has been reached. Wait for the indicated reset interval before retrying. Invalid or revoked keys receive HTTP 401.

## Status and errors

- `200` — search completed.
- `401` — missing, invalid, or revoked API key.
- `404` — route not available in public mode or key not found during revocation.
- `422` — invalid query or pagination.
- `429` — per-key rate limit exceeded.
- `503` — search database unavailable.

The health endpoint is `GET /health`. OpenAPI/Swagger documentation is available at `/docs`.

## Operational limits and launch checklist

This release is a public-API implementation, not a claim that a hosted service is already live. The existing project uses one SQLite database and one worker process. For the initial hosted rollout, run a single API instance with persistent disk, HTTPS termination, and secure environment variables. Do not horizontally scale multiple independent instances against ephemeral or separate SQLite files: API keys, quotas, and search data must share the same persistent database.

Before announcing a production endpoint:
- deploy behind HTTPS;
- set `APOKOLIPS_PUBLIC_MODE=true` and a unique 48-byte-or-stronger admin token;
- configure exact allowed CORS origins (CORS is not authentication);
- attach persistent storage and back up the SQLite database;
- keep admin and API keys out of source control and browser bundles;
- monitor 401/429 rates, database health, disk space, and crawl queue status;
- publish a privacy/contact and indexed-page removal process;
- verify crawler policy, publisher requests, and data retention.

Public developer keys are for searching the indexed corpus only. They do not grant crawl, key-management, statistics, or administrative access.
